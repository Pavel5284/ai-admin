# Видео-демо: сценарий и раскадровка

Цель: за 2:30–3:00 показать, что бот не «красиво отвечает», а доводит запись до конца, не выдумывает и измеряет результат. Запись ещё не сделана; это готовый материал для съёмки.

## Подготовка

1. `docker compose down -v` (если нужна чистая БД), затем `docker compose up -d db mock-crm`.
2. `npm run kb:load` — база знаний в pgvector.
3. `npm run dev` — Telegram-бот. Если токена нет, записывайте консоль: `npm run chat`; в кадре будет тот же диалог, но без интерфейса Telegram.
4. Откройте Telegram Desktop, чат с ботом. Выключите уведомления и лишние окна.
5. Прогоните сценарий один раз без записи, чтобы не ловить таймауты.
6. Подготовьте в заметках реплики: их легко потерять в кадре.
7. Не показывайте `.env`, токен, ключи и вкладку с терминалом, где они видны. Если ключ мелькает — перезапишите дубль.

## Реплики для записи

Идеальная запись:

```text
Здравствуйте, хочу на мужскую стрижку завтра в 18:00
+7 916 234 56 78
да
```

Грязная реплика:

```text
ну эээ подстричся послезавтра часа в три, мужскуюстрижку
```

Самопоправка:

```text
завтра, нет, в четверг, в половине шестого
```

Вопрос по базе:

```text
сколько стоит детская стрижка?
```

Вопрос без ответа:

```text
а татуировки вы делаете?
```

Если записываете консоль, те же реплики вводите в `npm run chat`; ответы бота будут в терминале. Для видео лучше Telegram: видно, что это не «скрипт в терминале».

Не говорите «100% на holdout» и «бот работает в проде»: этого нет. Честное «100% на dev, holdout не передан» звучит сильнее, потому что проверяемо.

## Запись

- OBS Studio: Sources → Window Capture (Telegram Desktop) + Audio Input Capture (микрофон). Output → mp4, Video → 1920×1080.
- Проще: Loom или Win+G; ссылка появляется сразу.
- Пишите 2–3 дубля: первый почти всегда с паузой на ответе LLM.
- Субтитры: добавьте хотя бы русские auto-captions и проверьте, что «LLM» и «false-booking» распознаны.
- Загрузите на YouTube как Unlisted или в Loom. Ссылку — в README, в поле Website репозитория и в сопроводительное письмо.
