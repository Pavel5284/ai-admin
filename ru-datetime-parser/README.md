# ru-datetime-parser

Разбор русских дат, времени и телефонов из живой речи: числительные словами, падежи, слова-паразиты, типичные ошибки ASR. Только правила, без сети и без LLM.

Пакет выделен из проекта [AI-администратор для барбершопа](../../README.md): там он разбирает реплики клиентов до того, как включается модель. Здесь он живёт отдельно, со своими тестами и примерами.

## Что умеет

- **Даты:** «завтра», «послезавтра», «через три дня», «в следующий вторник», «в субботу», «23 октября», «23.10.2026», «23 числа», «на выходных».
- **Время:** «в 18:00», «в шесть вечера», «в половине шестого», «без пятнадцати шесть», «в четверть восьмого», «в полдень», «после обеда», «утром».
- **Телефоны:** «+7 916 234-56-78», «8 (916) 234-56-78», «9162345678», номер словами, неполный номер по частям, «два нуля».
- **Нормализация:** регистр, `ё → е`, пунктуация, слова-паразиты, числительные, небольшая таблица ASR-исправлений.
- **Самопоправки:** «завтра, нет, в четверг» — берётся последнее значение.
- **Неоднозначность:** «на следующей неделе» возвращает `ambiguous: ['date']`, а не выдуманную дату.

## Установка и запуск

Пакет не публиковался в npm; он лежит в репозитории и работает из исходников.

```bash
cd ru-datetime-parser
npm install
npm test          # тесты парсера
npm run typecheck
npm run demo      # примеры разбора
```

В основном проекте те же тесты запускаются корневым `npm test`: Vitest находит их по всему репозиторию.

## API

```ts
import { normalize, parseWhen, parsePhone, wb } from 'ru-datetime-parser';

const now = new Date(2026, 9, 15, 12, 0); // 15 октября 2026, 12:00

parseWhen(normalize('завтра в шесть вечера'), now);
// { date: '2026-10-16', time: '18:00' }

parseWhen(normalize('послезавтра после обеда'), now);
// { date: '2026-10-17', timeRange: { from: '13:00', to: '17:00' } }

parseWhen(normalize('на следующей неделе'), now);
// { ambiguous: ['date'] }

parsePhone('8 (916) 234-56-78');
// { status: 'ok', phone: '+79162345678' }

parsePhone('8 916');
// { status: 'partial', digits: '8916' }
```

### `normalize(text: string): string`

Приводит реплику к стабильному виду: нижний регистр, `ё → е`, чистка пунктуации, удаление слов-паразитов, ASR-исправления, перевод числительных в цифры. Сохраняет `:`, `-` и `.`, потому что они несут смысл: «18:00», «23-го», «23.10».

### `parseWhen(text: string, now: Date): ParsedWhen`

Возвращает `{ date?, time?, timeRange?, ambiguous? }`. На вход лучше подавать уже нормализованный текст. `now` передаётся аргументом: внутри библиотеки нет `new Date()`, поэтому тесты детерминированы.

### `parsePhone(text: string, draft?: string): PhoneResult`

Статусы: `ok` (нормализованный `+7XXXXXXXXXX`), `partial` (не хватает цифр, их можно накопить в `draft`), `too_long` (лишние цифры или неверный формат), `none` (цифр нет).

### `wb(src: string): RegExp`

Граница слова для кириллицы. Обычные `\b` и `\w` в JavaScript не видят русские буквы, поэтому библиотека строит регулярки через `wb('завтра')`.

## Правила, которые важно знать

1. **Рабочие часы 10:00–21:00.** «В пять» — это 17:00, «в половине пятого» — 16:30. Это настройка барбершопа, а не универсальная истина: для другого бизнеса константы `WORK_START`/`WORK_END` нужно поменять.
2. **Диапазон — не время.** «После обеда» возвращает `timeRange`, а не конкретный час: решение, какое окно предложить, принимает диалог.
3. **Дата не выдумывается.** Если день не назван, `date` отсутствует; «на следующей неделе» даёт `ambiguous`.
4. **Числа 10–19 не склеиваются со следующим числом.** «Без пятнадцати шесть» — это 15 и 6, а не 21.
5. **ASR-исправления — список, а не модель.** Он пополняется по мере находок: «назавтра» → «на завтра», «мужскуюстрижку» → «мужскую стрижку», «двеси» → «двести».

## Ограничения

- один часовой пояс и одни рабочие часы; праздники и особая логика салона не учитываются;
- телефоны только российские: 10 цифр с `9` или 11 цифр с `7`/`8`;
- нет относительных интервалов вроде «через полтора часа» и «в течение дня»;
- редкие падежи и диалекты могут не разобраться — тогда основной проект отдаёт реплику LLM или оператору;
- библиотека не ходит в сеть и не хранит состояние.

## Тесты

```bash
npm test
```

Тесты покрывают даты, время, телефоны, числительные и нормализацию: десятки табличных кейсов на падежи, цифры словами, ошибки распознавания, самопоправки и неоднозначности.
